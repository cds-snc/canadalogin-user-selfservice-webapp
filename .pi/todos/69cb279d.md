Objective

Add a standardized PR checklist and branch naming guideline to make migration PRs consistent and reviewable.

Work

1. Add .github/PULL_REQUEST_TEMPLATE.md with a migration checklist, e.g.:
   - Summary of changes
   - Files converted
   - How types were added (any/unknown used?)
   - Build steps run (npm ci, npm run build)
   - Tests run
   - TODOs and follow-ups
2. Document branch naming in CONTRIBUTING.md or README:
   - feat/ts/batch-a-<short-desc>
   - feat/ts/batch-b-<short-desc>
3. Add a small PR template snippet for reviewers to verify build passes and that import updates are included.

Acceptance criteria

- PR template file added
- README/CONTRIBUTING note added

Notes

- Keep checklist minimal and focused to avoid friction for small PRs.
